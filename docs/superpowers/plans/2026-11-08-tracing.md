# Distributed Tracing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Store traces in Tempo and follow one request from Traefik through the todo app to its database calls in Grafana, with links between traces and logs.

**Architecture:** Tempo (single binary) in a new `tracing` namespace receives OTLP/HTTP directly from Traefik and the todo app. Grafana gets a Tempo datasource (trace to logs) and a Loki derived field (log to trace).

**Tech Stack:** Tempo chart 3.2.1 (grafana-community), Traefik (k3s-bundled chart 40.1.5, `HelmChartConfig`), Spring Boot 4.1.2 + `spring-boot-starter-opentelemetry`, Argo CD, GitHub Actions image build.

**Spec:** `docs/superpowers/specs/2026-11-08-tracing-design.md`

## Global Constraints

- Namespace `tracing`; Tempo OTLP/HTTP `http://tempo.tracing:4318` (spans at `/v1/traces`), query API `http://tempo.tracing:3200`.
- Tempo chart `tempo` `3.2.1` from `https://grafana-community.github.io/helm-charts` (NOT `grafana/tempo`, which is deprecated). Retention `168h`, 5Gi `local-path` PVC, memory request 256Mi / limit 512Mi, `memBallastSizeMbs: 0`, metrics generator off.
- Sampling 100% (Traefik `sampleRate: 1.0`, app `management.tracing.sampling.probability: 1.0`).
- Sync policy as `loki`: automated, `prune: false`, `selfHeal: true`, `CreateNamespace=true`.
- **Ask before every commit, push, tag, and release, in this repo and in `~/Developer/java/todo`.** Imperative commit messages, small commits.
- Todo repo release: pushing a tag `vX.Y.Z` builds image `ghcr.io/sraeburn/todo:X.Y.Z`; this repo then bumps `appVersion` in `gitops/charts/todo/Chart.yaml` and `image.tag` in `gitops/apps/todo.yaml` ("Deploy todo X.Y.Z").
- Verification uses `helm template`, `kubectl --dry-run=server`, `kubectl`, `curl`, and Grafana's datasource proxy API (admin credentials from Secret `grafana-admin`, never printed).

## Review Focus

- Traefik rolling restart must not drop ingress; both replicas must come back Ready with the tracing flags (Task 3 curls the VIP during and after).
- The k3s-bundled Traefik chart (40.1.5) is older than the one used to test the values; the pod args must show the four tracing flags (Task 3 checks them).
- Traefik and todo spans must share one trace ID, not appear as separate traces (Task 5).
- Prometheus scrapes and kubelet probes hit `/actuator/*` on the pod every few seconds; they must not flood Tempo with root spans (Task 5 searches for them).
- Tempo being down or unreachable must not break todo requests (Task 5 scales Tempo to 0, hits the app, expects 200s).
- Tempo must not OOM at the 512Mi limit (Task 1 checks restarts; Task 5 rechecks under traffic).
- Log-to-trace and trace-to-log links must work in both directions (Tasks 2 and 5).

### Task 2: Grafana datasources

**Files:** Modify `gitops/monitoring/values.yaml` (`grafana.additionalDataSources`).

**Interfaces:** Consumes Tempo's `http://tempo.tracing:3200` (Task 1) and the existing `Loki` datasource (`uid: loki`).

- [ ] **Step 1:** Add a `Tempo` entry: `name: Tempo`, `type: tempo`, `uid: tempo`, `access: proxy`, `url: http://tempo.tracing:3200`, `isDefault: false`, with `jsonData.tracesToLogsV2`: `datasourceUid: loki`, `spanStartTimeShift: "-5m"`, `spanEndTimeShift: "5m"`, `customQuery: true`, `query: '{namespace=~".+"} |= "$${__trace.traceId}"'`. The doubled `$$` is required so Grafana's provisioning does not expand the variable itself.
- [ ] **Step 2:** On the existing `Loki` entry add `jsonData.derivedFields` with one item: `name: TraceID`, `matcherRegex: '"traceId":"(\w+)"'`, `url: '$${__value.raw}'`, `datasourceUid: tempo`.
- [ ] **Step 3: Verify the render.** `helm template monitoring prometheus-community/kube-prometheus-stack --version 93.1.0 -n monitoring -f gitops/monitoring/values.yaml | grep -cE 'type: tempo|derivedFields'` prints `2`.
- [ ] **Step 4:** Ask, then commit "Add Tempo datasource and trace links" and push.
- [ ] **Step 5: Verify.** `monitoring` app Synced/Healthy. `GET /api/datasources` lists Prometheus, Loki, Tempo; `GET /api/datasources/uid/tempo/health` returns `OK`; `GET /api/datasources/uid/tempo` shows `jsonData.tracesToLogsV2.query` containing `${__trace.traceId}` (single `$`); `GET /api/datasources/uid/loki` shows the `TraceID` derived field. If the Tempo datasource is missing after a minute, `kubectl -n monitoring rollout restart deploy/monitoring-grafana`.
